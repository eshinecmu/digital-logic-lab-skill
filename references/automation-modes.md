# 三种协作路线

三条路线使用同一套要求提取、状态记录、仿真验证、证据、报告和打包门槛，只改变谁操作以及何时交接。用户最新的明确文字可以随时切换路线。

## 路线一：全流程代办（默认）

用户提供实验文档、提交规范、模板和已有工程后，主动完成所有可由计算机可靠执行的工作：建立或修复工程、编写必要代码与测试、仿真、自检、XDC、综合、实现、生成 bit、软件截图、报告和提交包。优先复用已有正确内容，不让用户重复软件操作。

真实板卡上的拨码、按键、接线、测量和拍照由用户完成。若硬件已连接且工具允许，可先完成下载 bit 等软件动作；不能替用户声称已经观察到硬件结果。交接时尽量把操作合并成一批，逐项写明当前 bit、初始状态、操作顺序、预期现象、照片范围和输入组合。照片返回后核验、确定性裁剪并写入报告。

## 路线二：逐步教学

先形成完整路线和截图计划，但每次只给一个步骤或紧密相关的一小组步骤。每步写清操作位置、选择或填写内容、原因、保存位置、预期现象和截图要求。等待用户返回截图、文件或现象并核验后，再进入下一步；不能仅因用户说“完成了”就跳过关键验证。

发现错误时先定位根因，再给最小修改和判断方法。能让用户自己改时给精确操作并复查；用户明确要求接管时才代改。原理图美化保持逻辑不变，优先对齐、等距、从左到右、减少交叉与回折、统一标签和压缩无效留白。若功能也错，先修逻辑再排版。实验完成后由助手处理图片、撰写报告和打包。

## 路线三：协作搭建

助手先完成机械性准备：打开或创建软件工程、选择正确器件和语言、建立目录与文件、录入手册明确给出的完整代码片段或接口骨架、创建仿真与约束位置、保存工程，并停在用户可直接开始原创设计的状态。

Logisim 的固定接口也属于机械性准备。对每个要求用户绘制的电路，先创建对应子电路，并依据手册放置全部已明确的输入、输出引脚；使用手册中的信号名或端口名标注，设置输入/输出方向、位宽及手册明确的有效电平等属性，按“输入在左、输出在右、同类信号对齐”的方式整理版式。总线的拆分方式或位序只有在手册明确时才预设，不推测缺失接口。不得提前放置内部逻辑器件、推导门电路或完成内部接线；用户接手后只需完成核心逻辑。

用户负责在预置接口之间放置逻辑器件并完成内部接线，以及编写手册没有给出的设计代码或测试逻辑。接口声明、完整代码片段和固定约束可以录入；功能描述、真值表、逻辑表达式要求或伪代码不视为“手册已给代码”，不能提前替用户生成完整答案。交接时列出已创建文件、已放置的接口及其属性、手册来源、用户 TODO、完成标准和需回传的文件或截图。

用户交回成果后保留其结构，只做通过功能和工具检查所需的最小修正，例如语法、端口、位宽、接线、组合逻辑覆盖、顶层和约束；说明改动原因并留下最小可运行检查。随后由助手接手仿真、综合、实现、生成或加载 bit、软件截图、报告和打包。真实板卡操作仍按路线一交给用户。

## 共同边界

- 三条路线都不伪造仿真、下载或实物结果。
- 切换路线不扩大外部上传、登录、提交或不可逆操作的权限。
- 报告始终区分理论预期、工具实测和用户实物确认。
- 只有全部必交材料通过检查后才能称为“可提交”；不自动上传或消耗提交次数。
