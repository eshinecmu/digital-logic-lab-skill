# 泛化的提交筛选与打包

## 从文档提取规则

逐项提取：提交单元与编号、目标平台、必交材料、是否要求完整工程、文件/包命名、模块名、归档格式、目录层级、附加文件限制、文件大小和提交次数。未知字段保留未知；不要默认所有课程使用 ZIP 或根目录平铺。

形成用户可核对的清单：实验编号｜候选实际文件｜必交/依赖/证据/中间产物/不明确｜来源页码｜验证状态。

## 筛选依据

1. 明确必交文件纳入；说明理由和来源。
2. 检查源码引用、include、数据文件及工程依赖。完整工程要求纳入重建所需资源；严格指定文件清单与额外依赖发生冲突时先解决，不能悄悄增加文件。
3. 图片和日志通常用于报告，仅在规范要求时单独提交。
4. 排除无关旧版、缓存、锁文件、中间构建目录，除非要求明确包括它们。
5. 不只凭扩展名匹配。核对模块/实体名、顶层、器件、约束和构建记录；选择对应源码版本的产物。
6. 缺少必交材料时先搜索历史和关联目录，再在授权范围内生成。无法取得的物理证据列为缺项；不制造文件或伪造结果。

## ZIP 辅助脚本

先建立 JSON 清单，要求所有 source 为实际绝对路径，member 为包内路径。`flat` 为根目录平铺，`tree` 允许指定层级。报告若应单独提交，不塞进实验 ZIP。未通过要求核对前不要执行打包。

```json
{
  "archives": [{
    "name": "学号-姓名-实验编号.zip",
    "layout": "flat",
    "files": [
      {"source": "C:/实际目录/design.v", "member": "design.v"},
      {"source": "C:/实际目录/design_tb.v", "member": "design_tb.v"}
    ]
  }]
}
```

运行：

```text
python scripts/package_submission.py manifest.json --out 提交目录 --check
python scripts/package_submission.py manifest.json --out 提交目录
```

脚本预检路径、重复名、空文件和已有输出；拒绝覆盖，更新包应选择新目录。生成后检查 CRC、包内路径及逐文件 SHA-256；打印清单。它不替代 HDL 仿真、模块名检查、报告视觉检查或课程要求审查。非 ZIP 交付用对应原生工具并执行同类检查。

## 最终门槛

按必交清单核对数量、名称、后缀和目录结构；对应测试能独立运行；构建结果属于正确设计；报告和证据一致。给出交付路径及各平台的提交对应表。只有用户要求上传才执行；提交后读取真实回执，排队状态不是通过，失败后先诊断再考虑剩余次数。
